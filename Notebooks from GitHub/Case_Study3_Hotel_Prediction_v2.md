# Technical Documentation: Hotel Prediction with Hybrid Collaborative Filtering (v2)

## 1. Notebook Overview
This notebook, authored by D. Akman, details the implementation of a Hybrid User-Based Collaborative Filtering (CF) recommender system. Its primary objective is to predict the next hotel a user is most likely to view. This challenge is approached as a recommender system problem, specifically addressing the "next item to show" scenario commonly found in e-commerce and booking platforms. 

The methodology leverages explicit user-hotel interaction data, essentially the browsing history, and combines it with demographic information, specifically the user's home continent and gender. This combined approach is referred to as "Feature Augmentation," where demographic features are appended to the user-hotel interaction matrix, increasing the dimensionality of the data before similarity computations. The core assumption of the notebook is that demographic information is highly predictive of hotel preference, and thus it is given twice the weight of the actual hotel browsing preferences during similarity calculations.

The notebook guides the reader through a structured workflow starting from raw data ingestion from three separate TSV files (`users.txt`, `activity.txt`, and `hotels.txt`). It performs exploratory data analysis (EDA) to understand the distribution of users and hotel ratings. Subsequently, it preprocesses the data by encoding categorical variables (dummy encoding gender and one-hot encoding home continent) and scaling numerical variables (hotel star ratings). The core modelling phase involves constructing an augmented interaction matrix, applying Singular Value Decomposition (SVD) for dimensionality reduction, and computing a user-user cosine similarity matrix. Finally, it uses this similarity matrix to predict the next hotel for every user, employing a multi-tiered fallback strategy to handle edge cases, and outputs the final predictions to a file named `dakman_predictions.tsv`.

## 6. Conclusions and Recommendations
This notebook presents a fully functional, end-to-end implementation of a Hybrid User-Based Collaborative Filtering system. The code is well-structured, combining demographic data with behavioral logs through matrix augmentation. The implementation of a multi-tiered fallback mechanism demonstrates a strong practical understanding of the edge cases inherent in recommender systems, ensuring 100% prediction coverage for the user base.

**Recommendations:**
1. **Implement an Evaluation Framework:** The most critical deficiency is the lack of performance validation. To transform this from an operational script into a validated model, a hold-out validation strategy must be implemented. Masking the last viewed hotel for a subset of users and evaluating the model's ability to predict it using metrics like Hit Rate or NDCG is essential to prove the model's actual value.
2. **Re-evaluate the Deterministic Tie-Breaking Bias:** The practice of sorting the data by hotel ID ascending forces the prediction loop to consistently recommend the lowest-ID hotel when multiple options exist from a similar user. This arbitrary bias should be replaced with a true random selection using a seed, or by selecting the hotel that the similar user rated the highest.
3. **Hyperparameter Tuning via Grid Search:** The weights assigned to demographic versus behavioral data (`hotel_ratings_max_value = 0.5`) and the dimensionality of the latent space (`n_components = 10` for SVD) were chosen arbitrarily. With an evaluation framework in place, these hyperparameters should be systematically tuned via grid search to identify the optimal configuration that maximizes prediction accuracy.
4. **Reconsider Implicit versus Explicit Feedback:** The interaction matrix uses the hotel's static `star_rating` as the interaction value. This implies that viewing a 4-star hotel represents a "stronger" or "larger" interaction than viewing a 2-star hotel, which is methodologically flawed. Browsing history is implicit feedback. The matrix values should ideally represent a binary (1 for viewed, 0 for not viewed) or the frequency of views, rather than the intrinsic quality rating of the item being viewed.
